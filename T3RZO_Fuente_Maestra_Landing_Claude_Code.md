# 39. RECOMENDACIONES DE IMPLEMENTACIÓN PARA CLAUDE CODE

Estas recomendaciones sirven para que la información de marca se traduzca bien a código.

## 39.1 Separar contenido de componentes

Evitar hardcodear todo el texto dentro de un único componente.

Idealmente organizar:

```text
src/
  components/
  sections/
  data/
    brand.ts
    productFamilies.ts
    faqs.ts
  assets/
    brand/
    products/
```

La estructura exacta depende del stack real.

## 39.2 Crear una capa de contenido

Los textos y datos variables deberían poder modificarse sin tocar toda la UI.

Ejemplo conceptual:

```ts
export const brand = {
  name: "T3RZO Autopartes",
  founded: 2019,
  primaryColor: "#20245C",
  accentGreen: "#00B541",
  accentRed: "#FF0000",
  marketplaceUrl: null,
  wholesaleUrl: null,
}
```

No colocar URLs falsas.

## 39.3 Nunca usar lorem ipsum en producción

Si falta contenido, usar `[CONFIRMAR]` de forma visible durante desarrollo.

## 39.4 No inventar métricas para decorar

Evitar:

```text
+10.000 productos
+5.000 clientes
99% satisfacción
25 países
```

salvo fuente confirmada.

## 39.5 Accesibilidad

- contraste suficiente;
- alt text descriptivo;
- navegación por teclado;
- botones con nombre claro;
- respetar `prefers-reduced-motion`;
- no depender únicamente del color para comunicar.

## 39.6 Performance

Las imágenes reales de producto y packaging son pesadas.

Optimizar:

- WebP/AVIF cuando sea posible;
- `srcset`;
- lazy loading;
- tamaños correctos;
- no cargar 10 MB para una miniatura;
- mantener el original como fuente.

## 39.7 Animación

Usar animaciones para jerarquía y percepción premium.

No usar animación como decoración permanente.

Preferir:

- entrada suave;
- parallax leve;
- transición de cards;
- líneas técnicas;
- zoom controlado de producto.
